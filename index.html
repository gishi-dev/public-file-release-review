架空の店舗 / 社員10名の公開デモ

公開フォルダーのファイルを、1件ずつ確かめる

一覧を整理 → 理由と確認事項を照合 → 人が扱いを記録 → 確認票を書き出す

ファイルの中身は持ちません。実際の移動・削除・公開・送信は行いません。

書き出しは記録上の判断で、公開サーバー・CDNの残存やファイルの中身を確かめた結果ではありません。点数や適合判定は出しません。

公開の意図と種類から整理します。「見当たらない」は「ない」という確認になりません。private というフォルダー名も配信対象外の証拠にはなりません。

役割表と確認する観点

IPAの自社診断の観点を要約：No.4 共有する範囲、No.5 バックアップの保管、No.19 ウェブで公開する情報。これらは整理の観点で、適合判定ではありません。

    3. 一覧の入力と候補の取り込み

    自分の管理する公開フォルダーを想定した架空の一覧だけを使ってください。ファイルの中身や認証情報は入力できません。変更した行は再整理待ちになり、AIは再処理しません。

    選んだ行を編集 / 行を追加

    一覧をCSV・JSONで貼り付ける

    CSVの見出しは path,type,purpose,creator,created,intent。JSONは同じ6項目の配列。空欄は null となり、未確認として扱います。各項目は改行を含まない1行で入力してください。最大100行です。

    任意の生成AIや人が作った候補JSONを取り込む

    下の指示と現在の入力をコピーできます。この画面から外部に送りません。コピーした内容に架空データだけがあることを確認してください。

    候補JSONは version・revision・inputs・candidates の4項目。version・revision・inputsはコピーした値をそのまま使い、candidatesには path・reason・questions（文字列の配列）だけを書きます。扱い・担当・期限は含めません。一部の行だけでも取り込めます。

    4. 確認票と判断の履歴

    「確認待ち」も担当・期限を記録すれば、記録上の判断として確定できます。対応の完了とは別です。未記録や担当・期限の不足がある間は確定できません。
